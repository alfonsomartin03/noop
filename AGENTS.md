# NOOP — agent reference

Single LLM-maintained entry point: rules, current state, routing and file index. Read §0–§4 first, then only the component and index entries you need (`rg -n '^##|^###' AGENTS.md` to jump). Source and tests win over this file; other docs and source comments can be stale (§4). Paths are repository-relative.

## 0 · Maintenance contract (every program change)

1. `git status --short` first; preserve unrelated work. Read affected source and tests.
2. In the same task, update the affected §3 bullets, §5 settings, §7 index lines (add/move/remove files), §8 verification and a §9 log row. Keep entries terse; no source bodies, logs, health data, credentials or signing values.
3. Mark what is implemented vs tested vs hardware-confirmed vs unknown. Never imply tests pass because test files exist.
4. §9 keeps the latest 8 rows; fold older context into §3/§4. Do not create a second state-summary file.
5. Before handing back, re-run the index check in §8 so §7 matches the tree.
6. After a branch is confirmed merged, remove its clean worktree and local branch; remove its remote branch only after the hosting service confirms the PR is merged.

This is a convention, not CI: reconcile with the working tree before trusting it.

### BLE, charging and collection

- `BLEManager`: scan → connect → discover → bond → subscribe → per-characteristic reassembly → decode/route/store/sync; `DeviceFamily` selects 4.0 vs 5.0 GATT and header framing.
- `BluetoothChoice` (`noop.bluetoothChoice`): records the system answer; Settings ▸ Strap toggle. While declined, no `CBCentralManager` at launch unless macOS reports allowedAlways. Ad-hoc rebuilds still re-prompt; only stable signing (`Local.xcconfig`) fixes that.
- Liveness (`BLEManager.linkLooksStalled`): keep-alive (30 s, Mac-side only) bounces the link only after 120 s of silence while realtime is wanted, or >20 min (`idleSilenceLimitSeconds` = pull interval + 5 min) when idle. An idle, discharging strap is silent for minutes; the old flat 120 s limit reconnected it (handshake + battery poll + history pull) every ~2.5 min (unified log 2026-11-10).
- Reconnect: 3 s rescan after unintended disconnect, plus a 15-min watchdog (`BluetoothChoice.reconnectIntervalSeconds`) that cancels a stalled connect and rescans while open and disconnected; skipped after user Disconnect. `LiveState.nextReconnectAt` drives the Settings caption. Not hardware-tested.
- Charging (`ChargingModel`, WhoopProtocol): attachment and activity are separate facts with source, event time, receipt time and connection UUID (`LiveState.beginConnection` per connect). On disconnect/reconnect the last known facts carry over marked held (`ChargingModel.Hold`, `ChargingEvidence.heldUntil`): hidden while disconnected; after reconnecting shown "last reported …" until the next report — held "charging" (and its attachment) lapses after `chargingReportWindow` 90 s without one, held "not charging" waits for the next report (≤ `factMaxAge`). Held facts never stamp readings (`confirmedCharging`), so alerts ignore them. Observed cadence (fw 50.43.1.0 unified log): event 3 pushed live every ~30 s while charging, per ~1 % step (hours apart) while discharging. Events 7/8 → activity; 5.0 event 3 (BATTERY_LEVEL, ~every 30 s while charging) byte 9 bit 0 → activity (`batteryEvent5`; confirmed fw 50.43.1.0 on 500 stored events; restores charging after a reconnect, since 7 is sent only once; never implies attachment; every report applies and holds until the next; the event's soc also feeds `updateBattery` as source `.event`); live event 29 (STRAP_CONDITION_REPORT, every 10 min) u16 @6 = soc × 10 (`conditionSocPercent`; locally confirmed vs event 3 on stored pairs, seen live once in C02a) also feeds `updateBattery` (`.event`, no charging flag); 21 → attached (and clears a "not charging" that was only inferred from detachment); 22 → detached + not charging. `Whoop5Charging.packInfo` (151, #41): NOOP sends `[01]` (`packInfoPayload`; `[]` is always answered FAILURE `01`+zeros = `unavailable`, no fact). SUCCESS presence 1 = `present(rawCharge)` → attached; revision + zeros = `absent` → detached, not charging, not full; other SUCCESS shapes `answeredUndecoded` (no fact).
